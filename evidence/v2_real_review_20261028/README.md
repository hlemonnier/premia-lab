# V2 independent replay evidence

Read the prospective `PLAN.md`, then `pre_run_review.json`. The review uses
unchanged strategy bytes and the employer's original `score.load` and `score.run`.
`branch_source_manifest.json` pins every one of the 48 V2 branch additions.
The original supplied review brief is retained byte for byte.

## Successful runs

- `run_v2_001`: exact four-file packaged V2, gamma 200/cap .05/gross 5.
- `run_c09_003`: exact original C09 package, compared against the original
  canonical audit ledger over the full economic run.
- `paired_readback.json`: descriptive full-run comparison of the two above,
  following `PAIRED_READBACK_PLAN.md` and its explicitly recorded output-path
  correction. All four resampling constructions are retained.

Each successful run has its executed harness, copied clean strategy/scorer,
source identities, input CSV hashes and actual array layout/dtype, environment,
unrounded daily ledger, per-decision observations, summary and output hashes.
The V2 observer captures existing forecast coefficients and allocator outputs;
it performs no additional forecast regression or portfolio optimization.

The paired workflow consumes only saved ledgers. Its bootstrap fractions are
descriptive, not posterior probabilities or selection-adjusted p-values. It
compares the packaged leveraged V2, not Claude's unlevered research variant.

## Preserved failures

`run_c09_001` and `run_c09_002` are audit-harness signature-forwarding failures,
not strategy failures. They produced no scored ledger. Their copied sources,
input identities, original harness versions and tracebacks remain available.
The corresponding first two paired invocations failed on the missing ledger.
`HARNESS_FAILURES.md` documents both interface corrections. The third comparator
run uses the scorer's own named-argument adapter and succeeds.

## Rerun and portability

Exact historical commands are in `rerun_v2.txt`, `rerun_c09*.txt` and
`rerun_paired.txt`. Use fresh output directories when repeating a policy replay;
the harness intentionally refuses to overwrite evidence. Substitute only the
project, package and source-data locations on a different machine. Restore the
original ZIP with the hashes recorded in the plan. The branch source is pinned
to `afed8d0cb017acda151c4ea262fc30db7568a4bb`.

Large `.npy` arrays are reproducible local outputs and are deliberately omitted
from Git under the repository's existing rules. Their hashes are retained in
the run manifests. All numerical claims in the review can be inspected in the
committed daily/decision CSVs and summaries. Some companion synthetic-audit
manifests also record generated bytecode/NPZ files; these remain reproducible
local execution outputs and are not publication source files.

The main run's timing includes observation overhead and is not a new century
runtime certificate. No future-period holdout was created. No model choice or
policy parameter was changed as part of this review.
