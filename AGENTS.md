# Project maintenance

Premia Lab is a research project, not a recruitment submission workspace. Keep the public entry point and `model_n0/` as the sole maintained policy. New research belongs under `research/`, with a hypothesis and verification contract documented before implementation. Preserve negative findings and distinguish code checks from economic evidence.

The active numerical modules and dependency pins remain frozen during documentation/repository work. Verify `docs/runtime_manifest.json` and the entry-point AST; do not change numerical rules merely to make a check pass. Public tests use an independently generated fixture, not the withheld benchmark.

Keep original third-party task material, raw benchmark inputs, private messages and credentials out of the publishable tree. Archive imported research using content-addressed objects and explicit branch/path provenance. Do not overwrite distinct versions or represent redacted files as byte-identical originals.

The legacy repository history contains private source material and must not be made public as-is. Publish a new clean Git snapshot with the publication utility instead. Never publish private data, change visibility, rewrite history or delete additional references beyond the user's authorization.

Use first-person singular when writing Hugo's research narrative. Do not invent personal implementation or reviewer contributions. Do not claim a separate N0 review, fresh holdout, independent-human audit or live performance.

Before a content release run `python -m unittest discover -s tests -v` and `python tools/check_project.py`. Do not merge raw data, caches, generated bytecode or artifacts into the maintained project.
