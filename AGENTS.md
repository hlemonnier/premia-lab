# Project maintenance

Premia Lab is a public research project at `hlemonnier/premia-lab`, not a recruitment
submission workspace. Keep the public entry point and `model_n0/` as the sole
maintained policy. New research belongs under `research/`, with a hypothesis and
verification contract documented before implementation. Preserve negative findings
and distinguish code checks from economic evidence. Keep only `main` as the durable
repository branch unless the owner explicitly changes that policy.

The active numerical modules and dependency pins remain frozen during documentation
and repository work. Verify `docs/runtime_manifest.json` and the entry-point AST;
do not change numerical rules merely to make a check pass. Public tests use an
independently generated fixture, not the withheld benchmark.

Original maintained code and associated documentation are MIT-licensed. Preserve
LICENSE and the scope in NOTICE.md; do not relicense external material. The owner
published the existing history in place. That history was not sanitized by renaming
the repository. Do not add original third-party task material, raw benchmark inputs,
private messages or credentials. Do not rewrite history or change visibility without
explicit authorization.

Archive imported research using content-addressed objects and explicit branch/path
provenance. Do not overwrite distinct versions or represent redacted files as
byte-identical originals. Repository description/topics require an administrative
write; documenting desired settings does not mean they are live.

Use first-person singular when writing Hugo's research narrative. Do not invent
personal implementation or reviewer contributions. Do not claim a separate N0 review,
fresh holdout, independent-human audit or live performance.

Before a content release run `python -m unittest discover -s tests -v` and
`python tools/check_project.py`. Keep documentation-only work separate from numerical
changes. Do not merge raw data, caches, generated bytecode or artifacts into the
maintained project. See CONTRIBUTING.md for the public workflow.
