## 4. The causal clock and evaluator arithmetic

### Information available for day `t`

Use zero-based array indices throughout code and record CSV labels separately; supplied CSV labels run from 1 to 3,780. If `X[s]` denotes characteristics and `R[s]` returns:

- Prediction for day `t` may use `X[t-1]` and return history through `R[t-1]`.
- The latest completed one-day training pair is **`X[t-2] -> R[t-1]`**.
- `X[t-1] -> R[t]` is the prediction being made; its label is unavailable.
- Multi-day labels require all constituent future returns to have matured before the pair enters fitting.

All learned transformations obey that boundary: time-series scaling, imputation, feature selection, covariance estimation, clustering, PCA, volatility sizing and regime detection. Cross-sectional transformations of the latest already-published panel are permissible. Static known trading costs are available directly. [S1:79–95; S2:58–64]

`forecast` receives complete input arrays as a computational convenience. Row `t` must remain a function of earlier data only. Retraining schedules, warm-up lengths and preprocessing cannot depend on a fraction of the eventual input length. A longer continuation must not change decisions already made. State cached by `forecast` is subject to the same rule when consumed by `rebalance`; unused future elements of a causal forecast cache may legitimately differ.

### Daily accounting

Let `w_t` be positions earning day `t`, `r_t` its stock-return vector, `h_t` drifted positions, `a_t` the returned after-close target and `c` one-way costs. The official sequence is:

\[
p_t=w_t^\top r_t,\qquad
h_{t,i}=w_{t,i}\frac{1+r_{t,i}}{1+p_t},\qquad
C_t=\sum_i c_i|a_{t,i}-h_{t,i}|,\qquad
x_t=p_t-C_t.
\]

The next day's earning positions are `w_(t+1)=a_t`. The initial book is empty and its opening trade is free. Drift uses gross return `p_t`, not net return `x_t`; costs do not rescale the next target inside this evaluator. Costs belong to the same date's after-close trade, while that date's gross return was earned by the previous target. [S2:49–71]

Primary Sharpe is `sqrt(252) * mean(x) / std(x, ddof=0)`. Beta is the centered regression slope of daily **net** returns on that day's raw equal-weight stock return. Printed annual return is arithmetic mean times 252, not CAGR. Printed gross exposure uses the after-close target. [S2:74–83]

### Initialization and terminal convention

The first call is after array row 252 and receives **253 history rows**. Its target first earns row 253. With input length `T`, returned scoring rows are `253 ... T-2`, inclusive: `T-254` observations. The final input return at `T-1` is not earned, although the trade after `T-2` is charged. The printed rebalance average also excludes the initial discarded row. [S2:14,51,67–71]

Preserve these conventions. Do not modify the official scorer, insert terminal liquidation behavior or use knowledge of the supplied endpoint to improve the number. Supplemental accounting diagnostics must remain clearly separate.

## 6. Alpha discovery: questions before model families

### A. Characterize the available information

Within discovery, measure the characteristics' scales, tails, missing/constant behavior, cross-sectional variation, persistence and redundancy. Determine which behave as time-varying stock signals, persistent stock attributes or common time signals. Treat these as findings to establish, without assigning familiar economic meanings to anonymous names.

Examine lagged predictive association, response shape and stability across chronological subperiods. Separate broad-market prediction, relative-stock prediction and risk identification. A characteristic correlated with future raw returns may merely select high-beta stocks. Investigate signal decay over a small predetermined set of horizons—initially 1, 5 and 20 days—to understand whether expected value can survive costs.

For each diagnostic, record alignment, data window and interpretation before inspecting its result. Overlapping labels and correlated stocks create dependence. Use daily cross-sectional summaries and temporal consistency rather than treating millions of stock-days as independent evidence. A contemporaneous relationship can describe the data but is not a legal forecast.

**Deliverable:** a compact hypothesis map stating observed relationships, plausible mechanisms within this synthetic market, competing explanations, tests and rejection conditions. No model is promoted simply because one chart looks striking.

### B. Establish an interpretable benchmark

The first candidate family is a regularized pooled forecast using lagged characteristics and a fixed causal update schedule. A ridge-type model is a suitable starting candidate because shrinkage and coefficient stability are inspectable. Choose its scaling, target treatment and fitting history from discovery evidence; compare raw robustly scaled and rank-transformed information only when there is a concrete reason.

Measure prediction quality, coefficient stability and residual structure, then trade the forecast through an explicit low-beta, cost-aware policy. The supplied equal-weight strategy remains an infrastructure control and intentionally violates beta. The supplied naive mean–variance example illustrates an interface; its noisy means and slow daily solve do not prescribe our research path. [S1:163–171; `example_naive_mv.py:20–27`]

**Promotion condition:** correct chronology, a reproducible relationship, credible net contribution after market control/costs and an explainable failure story. No arbitrary minimum Sharpe is promised.

### C. Permit one evidence-led challenger

If stable residual nonlinearity remains, compare one restrained nonlinear family: an additive transform model or a shallow, tightly budgeted boosted model. Select the question before the tool. Fit frequency, complexity and regularization count in the total configuration budget.

The challenger must improve the same economic objective using comparable risk and execution treatment. Better training loss, gross IC or an isolated good year is insufficient evidence. If extra flexibility makes the response unstable, stronger shrinkage or the benchmark may be preferable.

A return-history signal, group-conditioned signal or interaction can replace an unsupported route when a specific residual diagnostic warrants it. This does not authorize a broad feature catalogue. Clusters and factor estimates used by live decisions must be causal; the provided full-sample clustered images are orientation material, not deployable grouping rules. [S1:175–179]

### D. Select deliberately

Use this executable selection rule, with each finalist's simplicity rank assigned before validation:

1. Require the causality, output-validity, tested-path safety and measured-runtime gates. Require pooled validation absolute net beta below 0.2, our conservative reading of the market-neutrality intent; the design goal remains around 0.1 for margin.
2. Rank eligible frozen finalists by **pooled daily net Sharpe** on indices 2016–3022, using the same observations and official formulas. Do not average the two block Sharpes.
3. Treat absolute Sharpe differences no greater than `1e-6` as numerical ties. Resolve those by the preassigned simplicity rank, then by lower measured runtime.
4. Report both blocks' Sharpe and beta, profit concentration and uncertainty. These diagnose fragility and unsupported claims; they do not become a retrospectively selected alternative ranking metric.

If using time-block resampling, freeze its rule from discovery and recompute both Sharpes on identical resampled blocks; a test of mean-return differences is not the Sharpe-difference question. Record uncertainty even when the prescribed ranking selects a winner. Do not impose an unannounced minimum Sharpe or mandatory positive score in each short block.

A diagnostic exposing an invalid implementation can fail the relevant hard gate. A finding that motivates redesign consumes the consulted validation information and must be documented as adaptive research. Do not introduce a revised fourth finalist after reading validation while retaining a clean-validation description.

## 7. Portfolio construction and computational design

Begin with a transparent risk approximation and an explicit market hedge. A shrunk low-rank-plus-diagonal model is a candidate upgrade if residual correlations justify it. Past-only factor/risk estimation, controlled refreshes and visible shrinkage are more useful than an opaque full covariance inversion.

Investigate a policy balancing expected return, a variance penalty and the actual linear transaction-cost term around drifted holdings:

\[
\mu_t^\top a-\frac{\lambda}{2}a^\top\Sigma_t a-\sum_i c_i|a_i-h_{t,i}|.
\]

This is a candidate control objective, not a proof of the optimal long-run Sharpe policy. A one-day expected gain below an entry cost may have value if it persists for many days. Conversely, a rapidly changing high-IC signal may be untradeable. Make the relationship between forecast decay, holding horizon and no-trade behavior explicit; never amortize away costs in the reported ledger.

Hold signal and risk estimation fixed when measuring the incremental value of cost-aware trading. Hold the signal and cost policy fixed when comparing risk models. Attribute performance changes to specific decisions, using the limited ablations to answer actual questions.

Estimate and monitor market exposure directly. The official condition concerns realized **net** beta, so gross hedging alone is not final evidence. Record both, pooled and by period, plus rolling sensitivity. The internal absolute-beta goal near 0.1 supplies margin; any revision must be justified before later result inspection.

Choose size and concentration safeguards from numerical and economic failure modes. Gross exposure and turnover are explanatory diagnostics, not separate employer objectives. Scaling changes position drift and therefore future costs, so exact multi-day Sharpe invariance to size must not be assumed. Record minimum growth denominators and large net losses. A finite stress suite cannot guarantee solvency for every possible future, particularly for a short book under an unspecified return process.

Do not assume a custom optimizer is necessary. Profile a credible formulation first. If a specialized solver is required, write its failure modes and independent expected outcomes, then isolated checks, then implementation. Test meaningful cases—known optima, cost-induced no-trade behavior, degeneracy, constraint interaction and failure recovery—rather than restating the implementation afterward.

Computational architecture should remain small: causal signal/state updates, risk state, portfolio decision and minimal helpers. Avoid daily dense decompositions, repeated full-history copies and retraining whose cumulative work grows quadratically. At 25,200 days, a float64 characteristics tensor alone is approximately 2.62 GB; each additional `(days,1000)` output channel adds roughly 202 MB. These are scale calculations, not an employer memory limit. Keep caches bounded where possible and demonstrate their growth.
